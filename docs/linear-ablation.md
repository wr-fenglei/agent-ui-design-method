# Linear 参考图的对照实验

**状态: 待执行**, 本协议测量在相同来源素材与任务上, 额外提供项目中的 Linear 风格基准图, 是否改变用户的选择, 以及设计与基准的相似程度, 既有十稿可以帮助提出问题, 本次对照所需的新样本尚未生成

| 阶段 | 计划内容 | 交付及验收要求 |
|---|---|---|
| 目标 | 分开检验用户偏好和视觉相似度 | 开始前登记主评审, 指标, 样本量和无效样本条件 |
| 准备 | 选 Anthropic Frontend Design, Mobbin, Appllama 三个来源, 各保留一份固定素材包 | 同一来源的两组输入只差一张 Linear 基准 PNG |
| 生成 | 每个来源做 3 对独立重复, 合计 9 对, 18 张画板 | 保留每次首个完成的导出, 输入清单和运行记录 |
| 盲评 | 先评偏好, 锁定记录后再展示基准评相似度 | 拆开记录两项结果, 全部评分结束后揭晓分组 |

## 准备输入

1. 使用项目的 [Quarry Linear 基准稿](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=11-7202) 导出 1440 × 940 的 1× PNG, 记录文件 SHA-256, A 组无附加图片, B 组只多这一张 PNG, 两组使用同一段提示词
2. 每个来源各准备官方样本, 独立样本与原图观察记录, 剔除既有十稿的设计图, 成稿规范, 反馈, Linear 文件链接及复用画板, 两组使用同一份来源素材包, 任务文案, 字体, 空白 Figma 文件, 通用绘图工具, 模型版本, 推理设置和时间预算
3. 每张图启动独立的新会话和工作目录, 关闭历史记忆与联网检索, 只提供本次清单内的文件, 记录素材包摘要, 模型标识和工具版本, 若环境能指定随机种子, 同一对两组取相同种子, 三次重复分别取不同种子, 接口未开放种子时记为"不可设置", 随机交错生成 A/B, 保留所有输出

两组都沿用同一发布事件, 时间戳和审阅动作, 这样得到的是该任务上额外看到一张图的影响, 模型训练中已有的产品知识, 共用简报继承的任务结构, 都保留为这次比较的背景

## 盲评和记录

- 偏好作为主指标, 由用户在相同屏幕, 相同缩放下看每对两图, 从"用于日常发布审查, 我选左图 / 右图 / 持平"选一项, 记下影响选择的一处细节, 此轮藏起基准, 文件名, 来源, 条件与生成记录
- 相似度作为独立指标, 锁定全部偏好后, 展示基准图, 重新随机配对展示顺序与左右位置, 逐对选"左图接近基准 / 右图接近基准 / 持平", 注明依据, 可选导航与详情的分区, 选中行的处理或主按钮的形状, 新旧左右位置分别保存映射, 最后统一揭晓
- 生成前约定无效条件, 例如空白导出, 损坏文件, 基准泄漏至 A 组, 两侧状态均需记录, 单侧无效则整对列为无效, 记录原因, 文字过小, 构图欠佳和遗漏用户操作均留在样本内供评判

每一对填写一行, "左 / 右 / 持平"记录当轮所见, 揭晓后再填对应条件

```text
匿名对号 | 偏好(左/右/持平) | 偏好依据 | 相似度(左/右/持平) | 对应细节 | 有效或无效原因 | 揭晓后: 来源/重复号/两轮左右映射
_____  | ________________ | ________ | __________________ | ________ | ______________ | __________________________________
```

报告每个来源与总计的计划对数, 有效对数 N 和无效原因, 分别记录偏好中 B 获选 n/N, A 获选 n/N, 持平 n/N, 对相似度单独记录同样三项, 两项指标分别报告, 并保留持平票, 9 对样本, 3 个来源和这位评审的选择支持描述本次结果, 历史十稿的影响百分比仍无法据此推算

## 继续定位某个设计变量

整张参考图同时暴露了版式, 颜色和字体, 若评语多次提到分割线, 可复制同一成稿, 只改变面板间 1 px 分割线的透明度, 预先记下两个取值, 固定底色, 线位, 文字, 尺寸和全部其他元素, 重新匿名评审, 将这次偏好归于指定画面的这项改动, 与整图参考实验分别报告
