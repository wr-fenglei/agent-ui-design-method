# 检查一页 Figma 稿

在 Figma 中配对 Figmosha, 进入仓库根目录, 用 `figmosha targets` 的文档 ID 和要交付的页面 ID 运行

```sh
python3 tools/figma_lint.py --target "$FIGMOSHA_TARGET" --page "$FIGMA_PAGE_ID" --json
```

四个顶层 Section 或 Frame 分别命名为「功能与任务」「参考实物」「组件与规范」「成稿」, 首屏是「成稿」的直接 Frame, 标题、业务数据和组件标签使用原生文字, 作者可自行安排各板的版式, 错误会给出规则、图层名称和节点 ID

| 检查 | 读取对象 | 能发现的错误 |
|---|---|---|
| 任务到首屏 | 每张任务卡的说明、组件实例或指向主组件的文字链接, 首屏实际使用的组件家族 | 任务没有对应控件, 样件没有用于实际界面 |
| [参考实物](reference-native.md) | 成对的来源卡、可见图片填充及其原图尺寸、取景、出处、观察和取舍 | 缺少比较对象、重复参考、尺寸或采用依据缺失 |
| [组件与规范](spec-native.md) | 原生字样、色样、链接目标的几何、组件变体、实例、对应产品局部, 有玻璃或背景模糊时检查材质对照 | 只有文字清单, 标称尺寸与图层不符, 重复样件, 状态在成稿里找不到对应组件 |
| 底色和分割 | 逐屏检查大面积工作面和可见分隔图层, 读取宽高、填充及透明度 | 局部取样漏掉的偏色侧栏, 过重或密集的分割线 |
| 多屏原型 | 提交多张成稿时检查有效目标、入口可达和返回路径 | 跳转目的地丢失, 状态无法返回, 只提交一张成稿时不要求添加原型画板 |

命令返回 0 表示这些自动检查通过, 1 表示需要改稿, 2 表示没有完成读取, JSON 中的来源链接仍须核实图文对应关系和接收者的访问权限

## 白底、深底与边界的判定

大面积面板包含占首屏面积 8% 以上的工作面, 还覆盖窄而贯穿的侧栏和横跨窗口的顶栏, 对可见实色按叠加后的 RGB 取样, 本项目的近白范围为三个通道均 ≥232 且相差 ≤4, 深色范围为三个通道均 ≤64 且相差 ≤10, 这两个范围是本仓库的视觉偏好, 玻璃、渐变或图像后方的实际效果要回到导出图检查

检查长分割线和面板描边的厚度及其与相邻底色的对比, 例如 1 px 且对比达到 2.4:1, 或 2 px 且达到 1.35:1 会报错, 同宽横线连续隔开短字段也会报告, 带多列数据的表格可以保留用于跟读的细线

## 在 1× 导出里核对画面

```sh
python3 tools/design_density.py first.png --json
python3 tools/design_palette.py first.png primary=100,80 selected=32,96 reading=280,160
```

第一条按像素定位大块空白、重复横线与短字段间距, 查看 `findings` 和 `manualReview` 的坐标, 第二条在指定点检查本项目限制的绿色角色, 三个示例坐标须换成首屏上按钮、选中项和阅读底的实际位置, 避开字形和边缘

打开首屏和独立样件的原尺寸导出, 用同一对象编号逐项核对数值和文字, 实际看长标题、图标居中、对照是否同尺度、留白和视觉重点, 一条被报告的横线如果承担跨列读数, 记录它连接的字段, 参考出处、审美判断和业务结果需要结合画面核验

已有 PNG 清单可以用 `python3 tools/design_lint.py spec.json --json` 检查对齐、文字对比及素材切换记录, 新稿的主要检查直接读取 Figma
