# lint 检查什么

在仓库根目录运行, 需要 Python 3.9 或更新版本, 检查过程使用本地文件

| 命令 | 用途 |
|---|---|
| `python3 tools/verify.py` | 验证仓库中恰好有三个案例、每例三张不同的 PNG, 原始整屏的指纹和首页链接正确 |
| `python3 tools/design_lint.py --case linear` | 列出所选案例的三张图、尺寸和 SHA-256 指纹, 示例名可替换为 `shadcn-ui` 或 `apple-glass` |
| `python3 tools/design_lint.py 交付目录/design-system.json` | 检查这份设计交付, 逐项打印错误位置与实测值, 成功返回 0, 缺项或不符返回 1 |
| `python3 tools/design_lint.py 交付目录/design-system.json --json` | 将同一检查结果输出为 JSON, 方便 Agent 读取和复跑 |
| `python3 -B -m unittest discover -s tools -p 'test_*.py'` | 运行回归测试, 验证完整样例可通过, 缺项和错误样例会报错 |
| `node --test tools/test_export_text_layers.js` | 验证 Figma 文字导出器对隐藏、裁切、混排等图层的处理, 此项开发测试需要 Node.js |

先复制[模板](../tools/design-system.template.json)到交付目录, 按真实画面填写, 导出图片路径以清单所在目录为起点, 取样坐标按 1× PNG 从左上角起算

| 检查项 | 实际检查 | 典型报错 |
|---|---|---|
| 所选三图 | 校验案例、三张原图指纹和观察位置, 每张须写出可在图中找到的细节及本稿如何使用 | 缺过程图的观察, 或把另一例的规范图填进来 |
| 从参考到布局 | 检查参考与成稿的分区、字级、颜色面积和间距记录, 分区框应在画布内 | 分区越界, 只写了色值却没有说明使用位置 |
| 设计系统 | 检查任务、状态、证据和责任人, 字体、字号、行高、字重、间距、边界、圆角、图标、材质和适用位置 | 缺少行高, 用待填文字代替取值 |
| 界面调色 | 从参考和导出读取声明的界面色, 校对窗口、阅读面、主操作等角色, 检出被否决的墨绿与浅绿色, 以及媒体区域外的绿色界面 | 整条绿色顶栏, 将禁用的橄榄绿改名为成功色, 主按钮用色偏离选中参考 |
| 替换素材 | 对每个含可替换素材的状态比较同尺寸的两次导出, 检查画幅内确实换了素材, 并逐像素比较画幅外的可见界面 | 只改一个像素充当换图, 或换图后给按钮、顶栏换色 |
| 文字对比 | 每个状态从实际导出采集文字和邻近底色, 常规文字要求 4.5:1, 大字要求 3:1, 提供 Figma 文字层清单时还会在原生文字框内取样 | 只测了待审页, 或灰字在白底合格, 放进浅灰单元格后只剩 4.35:1 |
| 操作与控件变体 | 检查各屏主次操作是否关联实际状态, 主操作须提供默认态和适用交互态, 对应局部有可见差异 | 两张图的按钮相同, 或当前状态指向缺失的操作 |
| 按钮对齐 | 从待操作稿主按钮的默认态区域读出实际底面和图文像素, 比较上下留白, 提供同排按钮位置时一并检查纵向对齐 | 单行按钮的图文整体下沉, 或并排的决定按钮一高一低 |
| 交付与修订 | 读取规范板、研究板、待审与结果图, 检查路径、格式、重复截图、同尺寸的修订前后和发生变化的位置 | 缺少单独的规范图, 同图换编码充当结果页, 或圈出的修订区域没有变化 |

**配色如何判定** 对声明的界面角色, 参考图取样与本稿颜色每个 RGB 通道的容差为 8, 工具还会在作品框外采样, 检查遗漏的大片底色, 退稿中出现的 `#253E33`、`#315844`、`#345A46`、`#E8F0E9` 禁用于新稿的界面颜色, 原生窗口交通灯按其几何特征识别, 作品中的绿色可以保留

**换图如何判定** 测试时只替换作品图层, 字段、文案、选中状态、窗口大小均固定, 每个素材框至少 10% 的像素须有一个 RGB 通道变化达到 12, 且至少有 4 个像素变化, 框外的可见像素须全部相同, 这组测试可发现换图时一起变色的标题、底面或按钮

**按钮如何测量** 对于单行、单色底的决定按钮, 工具从 1× 图读出连续底面和实际文字、图标, 两者的纵向中心相差 4 px 及以上会报错, 有同排次按钮时填写 `variants.default.peerBox`, 可按顶部、中线或底部检查, 同样以 4 px 为界, 异形或渐变按钮用 `alignmentReason` 记录人工核对依据

**Figma 文字怎样全查** 在能调用 Figma Plugin API 的环境加载[文字层导出工具](../tools/export_text_layers.js), 用 `await exportTextLayers(figma, {review: "待审画板ID", done: "结果画板ID"})` 读取每个交付状态, 将返回值存为 `text-layers.json`, 在设计清单顶层填写 `"textLayers": "text-layers.json"`, 再运行同一个 lint 命令, 按报告核对需要人工查看的文字, 其他来源的平面稿可以逐状态填写取样坐标

三图记录能追溯到文件和位置, 制作者仍须用图片工具实际打开它们, 像素检查针对提交的截图、色样和范围, 字体绑定、分割线是否抢眼、单个异形图标的光学居中和原型操作由制作者在 Figma 与 1× 导出中自查, 视觉取舍交给用户
