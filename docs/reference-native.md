# 在 Figma 中制作参考实物板

从本题的业务操作写出至少 6 个需要决定的问题, 每个问题选 2 件能回答它的实物, 放在同一行或同一列, 例如翻译发布可以分别研究变量缺失的提示位置、两版译文的对照方式、建议的采纳范围、复查任务的依赖、语言就绪的条件和暂缓后的状态, 其他业务用自身的证据和操作决定比较内容 [Foldmap 参考板](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/?node-id=164-77285)

## 一张卡记录一件实物

在当前页顶层建立名为 `参考实物` 的 Section 或 Frame, 每张来源卡是它的直接 Frame、Group 或 Section, 同组两张卡分别填写 A 和 B, 对两个方案的取舍写在对应图片旁, 原始网页、下载图片和本地研究笔记可作补充

把真实截图作为卡内图层或实例内图层的可见 IMAGE 填充, 在画布上缩放到便于阅读的尺寸, 卡里有多个图片时, 将用于本次比较的图片图层命名为 `参考图`, 未指定时检查器读取卡中可见面积最大的图片, 观察文字和链接都放在卡内可见的原生文字层

| 文字字段 | 制作与验收 |
|---|---|
| 比较问题 | 两卡填写同一项设计决定, 如 `逐处核对修改后在哪里采纳建议`, 各组按不同问题配对 |
| 比较位置 | 填 `A` 或 `B`, 每组各一张 |
| 来源 | 写产品或原稿名称及具体界面, 将本字段或卡内的出处文字设为可点击链接, 可链接官方说明中的对应图片、带时间定位的产品演示或参考区之外的 Figma 原始设计节点, 核对产品、状态和访问权限 |
| 来源类型 | 填 `项目示例`、`官方产品或规范` 或 `同业务产品实物`, 本项目历史设计归入项目示例, 独立产品确实处理本题业务时可填 `官方产品或规范, 同业务产品实物`, 至少一张官方实物要有外部出处, 至少一张同业务产品实物要有可打开的原件, 两项可来自同一张图 |
| 原图尺寸 | 填原始位图像素宽高, 如 `762×311 px`, 使用未缩小的原位图或从原始像素导出的局部, 在 Figma 中缩放图片图层即可控制卡内显示尺寸 |
| 取景 | 填 `整图` 或 `裁切 x,y,w,h`, 分别表示原图左上角为原点的横向起点、纵向起点、宽、高, 四项单位均为原始像素, 如 `裁切 0,208,762,103` |
| 画面观察 | 写审阅者能在图上指出的内容, 包括操作、对象、位置或状态关系, 如某个词在原句中的删除和添加位置 |
| 本稿取舍 | 写明本稿哪个控件或区域采用、调整或舍弃所见做法, 如将单条建议的采纳入口放在该条差异下方 |
| 取舍理由 | 关联本题任务、数据或空间约束, 如一次只能采纳当前译文, 批量入口会让审阅者误判提交范围 |

有两种原生文字写法, 分层时使用上表字段作为图层名、文字内容填写实际值, 合并图注时每个字段写一行, 用 `字段: 实际值` 标出, 来源文字需在 Figma 中设置超链接

## 一组可照着制作的实物

比较问题为 `逐处核对修改后在哪里采纳建议`, 把两件原图按实际像素导入, 画布可分别缩放, 详情和决定如下

| 字段 | A | B |
|---|---|---|
| 来源 | Mozilla Pontoon 建议历史里的 DIFF [原图](../sources/localization/pontoon-suggestion-diff.png) · [产品文档](https://pontoon.mozilla.org/docs/localizer/translation-workspace/#viewing-translation-differences) | GitHub Pull Request 的 Suggested change [原图](../sources/localization/github-review-suggestion.png) · [产品文档](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/incorporating-feedback-in-your-pull-request) |
| 来源类型 | 官方产品或规范, 同业务产品实物 | 官方产品或规范 |
| 原图尺寸 | 762×311 px | 662×227 px |
| 取景 | 整图 | 整图 |
| 画面观察 | 底部记录启用 DIFF, 意大利语词组 `Sarà necessario` 显示删除线, `Dovrai` 紧跟在同一句内, 上方仍显示完整译文 | `Suggested change` 将旧行和新行上下排列, `Commit suggestion` 和 `Add suggestion to batch` 都在差异下方 |
| 本稿取舍 | 在译文建议里给替换的词组做行内标记, 保留原文供核查 | 将单条采纳按钮放在该条译文差异下方, 舍弃批量加入入口 |
| 取舍理由 | 交付前要逐词确认译文的改动范围, 译者仍需读完整句子的上下文 | 本稿的采纳操作只影响当前语言的当前条目, 单独的按钮能明确提交对象 |

同一原图可以研究两个确实不同的局部, 保留相同出处和原图尺寸, 按各自内容填写观察, 在 Figma 用裁切框展示相应区域, 或按 `w×h` 导出局部再放入卡中, 例如 Pontoon 的底部记录可标 `裁切 0,208,762,103`, 重新导出、移动图层或改名都不能用来把同一内容计作第二件实物

## 验收

运行[页面检查](lint.md), 查看 `referenceDepth.comparisons` 的 A/B 节点、各卡的 `originalSize`、`framing`、`image`、出处和三类来源统计, 图片大小按 Figma 的图片资源读取, 常规 Fit、Fill 与无旋转矩形裁切按可见的原始像素核对, 原生 Crop 模式读取裁切矩阵并检查重复, 精确取景、旋转和重编码图片的内容需要逐张打开原件复核 [Figma 图片 API](https://developers.figma.com/docs/plugins/api/Image/) · [Figma 图片填充](https://developers.figma.com/docs/plugins/api/Paint/)

用接收者账号打开原件, 对照产品、状态和取景, 在卡中逐条指出观察对应的位置, 确认同业务实物确实支持本题判断, 来源同一产品时标明实际产品名, 涉及控件宽度、颜色或材质的决定要复查原件数值、采样位置或材质在不同背景下的对照, 对图像无法测定的参数注明来源和待核实处
