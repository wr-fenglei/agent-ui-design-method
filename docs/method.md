# 先决定一屏里放什么

Linear 原稿里, 同一条任务在桌面占 399 px, 在手机占 340 px, 桌面行收起标签, 手机行再收起头像, 两边都留着状态、编号、标题和时间, 读者还能认出任务, 做新稿时也先决定哪些信息必须同时看见, 哪些可以打开详情再看 [桌面实例](https://www.figma.com/design/cytw6jxvr7NDe0K406hGME?node-id=7-303) · [手机实例](https://www.figma.com/design/cytw6jxvr7NDe0K406hGME?node-id=12-452)

## 从真实画面走到自己的布局

| 阶段 | 计划内容 | 交付及验收要求 |
|---|---|---|
| 定任务 | 写下用户正在看的对象、做决定需要的证据、下一步操作 | 给这三项填入本次内容, 标出必须同屏的字段、可展开的细节和应删的重复内容 |
| 读原件 | 打开同类产品正在执行这个任务的画面, 圈出用户先看哪里、选中后哪里变化, 从整屏追到控件状态和基础样式 | 图旁写出处、状态、本稿采用和舍弃哪一处, 想看控件怎样排列可以查 [Linear 三页原稿](../foundations/linear.md) 和[组件库的运行实例](../references/component-studies.md) |
| 比构图 | 探索新整屏时, 用同一份真实文案至少画两张布局草图, 让主要阅读区域或证据组织方式发生变化 | 例如同一组记录可以按时间上下排列, 或按字段左右对照, 缩到能同时看到两张整图, 说出第一眼看到哪块、哪个方案让证据容易比较, 留下选用和淘汰的理由 [同题案例](../cases/index.md) |
| 精排入选稿 | 把标题、正文、辅助信息、操作排出先后, 放入最长的一行和真实选中态, 用规范中的原尺寸组件绘制 | 每个区域都服务于这次操作, 可从一条记录读到对应结论和动作, 单个部件有疑问时只改其所在局部 |
| 看图再改 | 把实际导出与参考并排, 缩小检查视觉重心, 再以 1× 查看标题与正文的起点、字段列轴、字号和字色的主次、组内与组间的留白、分割线和按钮图文居中 | 对目测发现的问题保留一次改前和改后的同位置截图, 标明问题、改了什么、重新导出后看到什么, 一处都没有发现时如实记录 |

## 研究板放在成稿旁边

留下能说明选择的材料, 让接手的人看得到原图、尝试与结果

- **原图和采用理由**, 保留相邻内容, 标注出处、设备、状态和观察到的排版, 本稿自定的取值单独写, 研究输入框时保留普通与聚焦状态 [组件实物与测量](../references/component-studies.md)
- **候选和取舍**, 并排放构图草图并指出淘汰原因, 再放入选布局里的原尺寸组件, 用同一份文字标明它在屏上的位置, 对需要复用的组件提供可定位的主组件和实例
- **视觉修订**, 保留改稿对照, 例如步骤按钮的白边能标明点击范围, 顶栏底部的贯穿白线却把连续窗口切成两块, 因此选定稿保留按钮细边、移除顶栏白线 [步骤按钮样本](../references/still-components.jpg) · [重试路径成稿](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=118-68695)
- **本次另需验证的效果**, 用到玻璃时, 把壁纸、材质、内容和工具按钮按前后顺序列出来, 在真实背景上对照几个窗口区域, 用户选中的 Apple 全窗稿是一个可复查的例子 [三种窗口与材质研究](../cases/apple-glass.md)

参考与任务有冲突时, 先把处理限制在适合的部件, 再比较是否需要换回底稿做法, 例如历史换色稿中字与按钮底色的对比度从 4.70:1 升至 7.08:1, 按钮与相邻面板的对比度却从 3.78:1 降至 1.48:1, 检查时应同时看字和按钮轮廓 [换色实测](../evidence/still-history.md)

## 交付前做两次复核

1. **别人能否读懂**, 给不知道题目的人只看成稿, 请对方指出当前对象、支持结论的证据、还需谁做什么, 记录他实际读出了什么
2. **画面是否合适**, 设计者把成稿和选定原件并排目测, 说明哪一处重心、排版或部件仍有差异, 数值检查可核对尺寸与对比度, 审美取舍交给用户看图确认
