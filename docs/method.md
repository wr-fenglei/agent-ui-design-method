## 选择能回答设计问题的素材

| 想回答的问题 | 去哪里看 | 在记录里写什么 |
|---|---|---|
| 这个技能实际改变了什么 | 作者展示的同题前后图, 或独立使用者记录的操作与结果 | 写明任务, 版本或已知操作条件, 记录发生变化的控件与位置, 只附原文能确认的生成关系 |
| 这个产品怎样显示当前状态 | 从图库条目追到产品作者的文档, 运行页, 演示或更新记录 | 记下选中, 展开, 审核, 失败等具体状态, 库的收录与原作者的设计分别标注 |
| 按钮, 导航或输入框到底多大 | 打开能运行的组件, 记录主题, 视口和状态, 测量尺寸, 字体, 行高, 间距 | 把浏览器或 Figma 实测与从截图估计的值分别记录, 看不出的透明度, 阴影或模糊半径保留为未知 |
| 用户喜欢截图中的哪一部分 | 用编号图让用户圈出组件, 局部或状态, 同时记录不喜欢的处理 | 例如只选某张图的按钮, 采用范围就写"按钮", 背景, 卡片和整页颜色须另有依据 |

## 通过局部观察形成规则

每条写明适用的组件与状态, 可单独改变的变量, 这张稿采用的值, 原图提供的依据, 验收动作, 一个来源可以支持不同的画法, 例如 Sentry 支持"在选中记录下方展开", 本次案例将间隔定为 0 px, 将颜色换成警示色是另一项独立决定, 需要做单变量试验时, 把"色值和线宽"之类的组合继续拆开

| 变量 | 本例取值 | 怎样验收 |
|---|---|---|
| 脉冲的水平位置 | 1 秒对应同一绘图区, 按 83 ms 与 516 ms 线性定位 | 两点的水平差应为绘图区宽度的 0.433 倍, 检查刻度, 单位和标签 |
| 记录详情的出现位置 | 展开内容紧接选中行的下边缘, 间隔 0 px | 读者可从字段所在位置明确它属于哪一行 |
| 带图标按钮的居中基准 | 用实际文字宽度, 8 px 间隔和 15 px 箭头计算整组宽度 | 比较整组可见边界与按钮两侧内距, 再在 1× 导出上检查像素 |
| 状态的非颜色标识 | 重复写 Duplicate, 验证通过写 Passed 并配图标 | 即使不根据颜色, 也能回答哪笔是重复, 哪次回放通过 |

## 从规范到 Figma

1. 一个来源建立一份素材和规范, 每条规则带出处索引, 用 Figmosha 把它写进 Figma, 原图置入规范板, 标题或说明链接回出处
2. 在同一来源分区建立空白原生 Frame, 调用该来源的绘图函数, 十个绘图函数共用创建文字, 矩形, 矢量和加载字体的工具, 各自定义版式, 色值和控件
3. 为规范和素材图计算摘要, 发布设计时核对相同摘要, 增加参考或调整规格后, 先更新规范, 再更新对应界面, 稳定的 Figma 节点链接方便复查
4. 从实际 Figma 节点导出 PNG, 校正数值与目检发现的问题, 在原节点重新发布并导出, 更改本地绘图文件后, 以重新导出的结果为准

## 验收口径

- **内容**: 检查 9 个必需字符串, 再人工通读用户请求, Agent 结论, 两条记录, 修补后的回放及人工审阅动作, 确认数据之间的关系
- **原生几何**: 核对画板尺寸, 文字边界, 控件对齐与裁切, 对按钮连同标签和图标一起检查, 保留 Figma 节点读数和最终导出
- **合成对比度**: 导出成稿和临时隐藏文字的同一画板, 用原生文字色, 有效透明度与字形覆盖位置的背景采样计算亮度对比, 以 2 px 步长采样, 本轮脚本用 4.5:1 检查常规文字, 3:1 检查符合其大字条件的文字, 记录实际最低值, 结果限于该导出和该状态
- **目检**: 先在整屏定位任务和主操作, 再按 1× 检查图标中心, 浅色边框, 长文换行和选中范围, Impeccable 把结果与时刻的中心改为从事件节点坐标计算, 最终四处文字的可见中心与节点中心偏差在 0.5 px 内 [源代码](../drawings/impeccable.js) · [导出图](../cases/impeccable/design.png)
- **交付一致性**: 在 Figma 检查规范的来源链接, 原图数量和成稿归属, 对最终 PNG 计算 SHA-256, 仓库的离线检查可复核归档和校验值, 重新测量修改后的画板需要重新读取 Figma 并导出 [离线核验](../tools/verify.py)

审美反馈单独记录到具体组件和状态, 整屏候选同时变动多个变量, 可用于选方向, 要判断一个变化是否带来偏好差异, 复制同一稿, 只改一项, 随机左右位置再请用户选择 [实验协议](linear-ablation.md)
