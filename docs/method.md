# 制作方法与复盘

| 阶段 | 计划内容 | 交付及验收要求 |
|---|---|---|
| 定题 | 固定用户要做的决定、事件事实、设备和当前状态, 让各稿可以比较信息组织 | 本例给每位设计者同一张 1440 × 940 画板, 同一订单 TEST-8072, 同一份待人审阅的补丁 |
| 选参考 | 注明每个来源负责哪项决定, 标出用户喜欢和排斥的具体部位及状态 | 一条记录对应一个局部, 如选中导航行或带圆片的步骤按钮, 附出处和适用范围 |
| 做样件 | 从来源实物读取尺寸和材质, 把默认、选中或聚焦状态放进实际任务区域 | 建议先按 1× 确认一块含正文、选中行和操作的区域, 再铺开多个方案 |
| 独立绘制 | 各自从空白画板出发, 用同一组事实设计证据的顺序、排版与操作 | 每稿能说明一种布局解决了哪个阅读问题, 规范主组件可从实稿实例回溯 |
| 验收 | 从 Figma 导出成稿, 分别走查审阅流程、控件几何和视觉偏好 | 找到证据、验证结果和人工操作, 核对字号、图标居中、对比度与裁切, 修正后重导同一画板 |

## 哪些做法造成了返工

| 已撤下的迭代 | 实际观察 | 可复用的判断 |
|---|---|---|
| Still 换色稿 | 复制 Linear 稿后保留按钮几何, 文字对按钮底色的对比度从 4.70:1 升至 7.08:1, 按钮底色对相邻面板却从 3.78:1 降至 1.48:1, 用户点名不喜欢无描边的浅紫按钮 | 分别检查标签的可读性和按钮在背景上的轮廓, 这些读数是对反馈的一种解释 |
| 四个混合稿 | 分别复制 Linear、shadcn/ui、Untitled UI、Apple 底稿再替换材质, 用户只选中了侧栏的 `Release audit` 导航行 | 保留被选局部的图标、字重、内距和选中面之间的关系, 扩展到其他控件前单独看样件 |
| 五个不同题材的稿 | 播客剪辑、潮位分析、港口路线、印刷归档、书籍校样使用不同数据与操作, 后续改色保留文字和文字框位置, 用户认可改色后有改善, 仍要求重做 | 同时换题材、构图和风格会妨碍归因, 并排选方案时固定任务, 单独比较颜色时固定相邻背景和几何 |

第一组对比有图层与颜色读数可查, 各轮同时改变了多项条件, 单一来源对选稿的贡献仍需独立实验 [换色稿实测](../evidence/still-history.md) · [参考影响与实验设计](linear-influence.md)

## 保留的五稿怎样使用参考

**Linear 和组件库研究提供产品参照**, 用户提出调查请求, Agent 给出原始证据和回放结果, 人审阅 `checkout-event.patch` 并可继续追问, 五稿允许改变栏数、证据顺序与信息密度, 例如看间隔用时间线, 找两条记录的差异用对齐列, 审补丁用 diff 与回放结果 [项目 Linear 基准](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=11-7202) · [shadcn/ui 稿](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=47-20650) · [Untitled UI 稿](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=50-21410)

**Still 提供用户选定的组件, Apple 研究稿提供编写规范的方法**, 每份规范都摆出参考实物、材质与层级、原尺寸组件、研究依据和本稿定义, 分别记录从原件读出的值和本稿新增的决定, 五张实稿共使用 39 个链接到各自规范主组件的实例 [Still 组件](https://www.figma.com/design/AnEre9JbzJYfQdhaOGtJqW/?node-id=16-19446) · [Apple Liquid Glass 来源与设计规范](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=52-24248) · [五组规范与成稿](../cases/index.md)

| 部位或状态 | 采用的处理 | 要避免的处理 |
|---|---|---|
| 窗口和正文 | 环境色在外围, 窗壳白色 44% 配 28 px 背景模糊, 阅读面用 93% 的 `#FAFBFF` 承载日志或代码 | 把外围薄荷色铺成导航、按钮或正文的主色 |
| 步骤与顶栏 | 数字或勾放在步骤按钮的白色圆片里, 按钮细边标示操作范围, 顶栏与内容通过材质交界分层 | 在两层材质之间再加贯穿窗口的白线, 事件回放和重试路径两稿都按反馈移除了这条线 |
| 导航、状态和证据行 | 导航和状态保持单行, 窄证据行内保留标题与上下文, 选中时只突出这一行 | 将局部选中态放大成整块紫色面板, 或用同色表示可操作、已选中和已完成 |
| 后续提问 | 使用左侧加号、44 px 高、24 px 圆角的输入框, 聚焦只显示一层边线 | 让占位文字或图标偏离中心, 或在已有焦点边线上再套一圈 |

## 怎样验证一个设计决定

选素材时, 到官方组件或发布者的演示核对控件状态, 图库条目追到原产品, 标明直接测量、截图估计或本稿自定

一条规范记录一个可以改变的变量, 写明组件及状态、参考观察、本稿取值和验收动作, 例如日志详情紧接选中行的下边缘, 展开间距取 0 px [Mobbin 案例及依据](../cases/mobbin/case.json) · [对应绘图源](../drawings/mobbin.js)

整屏走查时, 读者应能指出哪条记录重复、修补后两次重试的结果、哪个操作还需本人确认, 局部走查时, 在 1× 成稿上核对图标和标签成组居中、两侧内距、长文换行和实际背景上的文字对比, 遇到半透明表面, 在相同位置导出有字和隐藏文字两张图, 以字形位置的实际背景测对比度, 顶栏白线等问题仍需看整屏 [双记录核证](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=118-68697)

判断偏好时, 复制同一画板, 例如只改变顶栏下方 1 px 横线的可见性, 固定填充、文字和间距再并排选, 把结果记成适用于该位置的规则, 对整张参考图的偏好则需要另做对照 [Linear 参考图的对照实验](linear-influence.md#待执行的对照实验)
