# 从一张底稿做出不同设计

例如订单被记了两次, 看时间线能知道两次相隔多久, 把两条记录并排就能看出哪里相同, 它们用同一份数据回答不同的问题 [事件回放](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=118-68691) · [双记录核证](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=118-68697)

## 动手做一份

| 阶段 | 计划内容 | 交付及验收要求 |
|---|---|---|
| 先挑一张底稿 | 写一句话说明用户要做什么, 到元设计页看这张底稿怎样帮助用户完成它 | 本例沿用 Linear 的调查和审阅流程, 每稿都能找到两条记录、Agent 的解释和等人审阅的补丁 |
| 从参考里挑一个地方 | 圈出喜欢的部件, 写明打算放在哪里 | 例如只取 Still 里带数字圆片的步骤按钮, 用来表示还要做的事, 在规范里留下来源和原尺寸样件 |
| 画一小块看看 | 把真实的记录、按钮和相邻背景放在一起, 按原尺寸看 | 读得出两条记录, 能看出选了哪一条, 也能找到待做的操作 |
| 再画整页 | 每稿从空白画板开始, 给每稿一个具体问题 | 看时间用时间线, 查字段用双列, 审改动把代码和验证结果放在一起, 各稿使用同一订单和待审状态 |
| 查一遍 | 从实际设计工具导出原尺寸图, 先按任务读一遍, 再看按钮和文字 | 能指出哪条记录重复、修补是否通过验证、谁来确认, 检查图标居中、文字裁切和对比, 修正后重新导出 |

可以从这里取材料 [Linear 元设计](../foundations/linear.md) · [参考库与找图方法](../references/README.md) · [可复制的任务简报](../templates/study-brief.md)

## 打开成稿, 指给另一个人看

- **先找到事**, 指出当前选的是哪项, 依据在哪里, 下一步要按哪个按钮, 如果标题、标签和按钮同时抢眼, 先调整字号、字重和留白
- **再放大到原尺寸**, 看图标和文字这一组是否居中, 两行相同字段是否对齐, 普通字和灰色小字在实际底色上能否读清, 过长的文件名或时间不能把按钮挤出去
- **只留有用的边线和颜色**, 临时隐藏一条线, 还能分清两块内容就可以删, 选中项同时有名称或标记, 让人能指出选了哪项
- **再导出一次**, 修好后打开交给用户的那张图, 逐项复看, 自动检查通过后仍要和原参考并排看控件的形状、文字层次和间距

## 两种设计放在一起不好看时

| 你看到什么 | 可以怎么做 | 怎么知道可以用了 |
|---|---|---|
| 原图的输入框和这次一样, 都用来追问 | 直接借这一处, 放入本稿的提示文字和输入文字 | 能读出文字, 能辨认输入位置 |
| 喜欢一条淡紫选中行, 原图文字短, 本次还要放很多字段 | 留下窄行表示选中, 详细字段放到下面或旁边 | 看得出当前记录, 字段也能读全 |
| 透明窗口好看, 代码却受到背景颜色干扰 | 缩小透明区域, 让窗口边缘透色, 正文放在浅色阅读面上 | 在真实背景上核对文字对比, 查看不同位置的文字 |
| 长按钮换色后很难认出是按钮 | 这一处先换回底稿的按钮, 如果仍想用新样式, 在同一局部只改一项再比 | 不靠猜测能找到审阅操作, 能说明哪项改动值得保留 |
| 用户这次要在地图上规划路线, 原底稿却围绕审补丁展开 | 重新写下主要任务, 另做一份适合路线规划的候选底稿 | 用户能在新稿中完成主要任务, 确认后再考虑收为另一套元设计 |

比较某个细节时, 可以复制同一画面, 只切换顶栏下的一条白线, 其他颜色和间距用同一份, 把选稿结果记在“顶栏底边”这一处

## Linear 和 Still 当时遇到了什么

**文字清楚, 按钮轮廓却变淡了**, 一次换色保留了 Linear 的按钮形状和尺寸, 字与按钮底色的对比从 4.70:1 升至 7.08:1, 按钮底色与周围面板的对比从 3.78:1 降至 1.48:1, 走查时这两处都要看 [换色实测](../evidence/still-history.md)

**用户喜欢的是一行, 还有按钮上的白色圆片**, 四个混合稿里用户只圈了 `Release audit` 的选中行, 在 Still 里选了带数字或勾的步骤按钮, 也指出不喜欢整块紫色面板和无描边的浅紫长按钮, 做这个系列时把淡紫留给窄选中行, 确认按钮单独选用有边界的表面, 环境的淡绿色也只用在窗外 [喜欢的组件](../references/still-components.jpg)

**换了题目, 就难以比较设计**, 旧五稿分别画剪辑、潮位、路线、归档和校样, 改色后仍被撤下, 保留的五稿都画同一个订单, 可以直接比较时间线、日志、重试路径、字段对照和补丁审阅 [五份设计与规范](../cases/index.md)

**按部位用材质**, 保留的五稿参考 Apple 的做法, 把原图、原尺寸部件和本稿取值放在一起, Still 的窗壳用 44% 白色和 28 px 背景模糊, 正文用 93% 的 `#FAFBFF` 阅读面 [Apple 材质研究](https://www.figma.com/design/scYOkdhE2byoPHW4Gk1aDL/Untitled?node-id=52-24248)

**把偏好记到具体位置**, 步骤按钮的白色圆片和细边保留下来, 事件回放和重试路径的顶栏白线则按反馈移除, 这些记录能解释具体设计决定, 单个来源的贡献还需要独立对照 [Linear 的影响与证据](linear-influence.md)
