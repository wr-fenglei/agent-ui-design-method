# 从参考原件画到新界面

「把左栏的玻璃铺到整窗」, 在 Figma 里要移动哪些图层?

在 Quarry 原稿里, 左栏下面有一张和桌面对齐的壁纸, 壁纸上面还有一层玻璃, 全窗稿把这两层移到窗口底部, 只把玻璃拉到整窗大小, 再清除挡住它的面板底色, 工具按钮仍用自己的表面, 这段过程可以在三张同内容的稿上逐项核对 [Apple 全窗案例与研究板](../cases/apple-glass.md)

## 画新稿时怎么做

| 阶段 | 计划内容 | 交付及验收要求 |
|---|---|---|
| 写下任务 | 说明谁在处理什么, 已发生什么, 哪一步仍等人决定 | 本例能从同一订单的两次记录看出重复发送, Agent 已在本地验证补丁, 用户仍需审阅 |
| 拆开底稿看 | 到 Linear 的 Screens 找选中的任务和 Agent 回复, 到 Components 查相应控件的状态, 再到 Foundations 查字体、颜色和间距 | 在整屏图旁标出将沿用的阅读顺序、组件和取值, 换业务时填入新任务的证据和操作 [打开原稿三页](../foundations/linear.md) |
| 带着问题找实物 | 例如要知道列表选中时如何变化, 打开运行中的组件, 点开一行, 同时保留普通行、选中行和邻近背景 | 截下能回答问题的区域, 标注来源与状态, 将能直接量到的值和截图中的观察分别写清 [找图方法](../references/README.md) · [两套组件库实录](../references/component-studies.md) |
| 先画规范和原尺寸部件 | 在成稿旁建研究板, 用自己的长标题、真实记录和动作制作样件, 试出适合这份稿的尺寸和层级 | 可以从样件找到参考实物、采用的位置和理由, 未验证的参数有标记 |
| 让每张稿解决一个问题 | 独立方案可以有不同的布局, 同题比较时共用数据和待审状态, 研究材质变化则复制同一画板来比较 | 看时间间隔用时间线, 对照字段用双列, 审改动用补丁和回放结果, 用户能从结论回到证据 [同题五稿](../cases/index.md) |
| 导出后按原尺寸检查 | 将实际导出与选中原件并排, 看图标与标签是否成组居中, 字号和字色是否分得出层次, 文字能否完整显示 | 在成稿上指出当前对象、证据和下一步, 同时核对控件和周围背景的边界, 修正后重新导出 |

## 研究板里放什么

让另一位设计者打开研究板, 能用其中的材料重做你选中的那一处

| 板上的内容 | 一个可以照做的例子 |
|---|---|
| 参考实物 | 对照 Apple Notes 的深色工具组和 iA Writer 的连续正文区, 保留带上下文的实图, 在每张图旁写哪一部分用于本稿 |
| 材质与层级 | 按从后到前列出壁纸、玻璃、内容和独立控件, 想判断折射时用带标线的背景对照模糊与折射的导出, 分别观察标线位置是否偏移、颜色边缘是否变模糊 |
| 原尺寸组件 | 放一行普通任务和一行选中任务, 加上本稿的图标和长任务名, 将画板里的实例链接回主组件, 尺寸以 1× 显示 |
| 研究依据 | 把测试条件写在数字旁边, 例如 shadcn/ui 的浅色桌面样例侧栏行高 32 px, 图标 16 px, 图文间距 8 px, AppKit 原生测量另记系统版本和 pt |
| 本稿定义 | 写清哪些结论来自原件, 哪些是本次选择, 例如全窗共用左栏的材质是本项目按用户偏好做的版本, 真实 Mac 应用和官方资料用于理解材质及控件 |

每条重要决定都可按这一行记录, **原件及状态 / 观察或实测 / 在本稿用在哪里 / 采用什么值 / 怎样复查**, 研究问题决定板上内容, 例如做输入框就测试默认、聚焦或错误状态, 做材质就检查它与实际背景的关系 [Apple 实例](../cases/apple-glass.md) · [组件库实例](../references/component-studies.md)

## 参考和底稿放在一起不合适时

- **局部有效, 就留在局部**, 旧四个混合稿里用户只选了一行 `Release audit` 导航, Still 系列因此把淡紫留给窄选中行, 步骤按钮保留白色圆片, 顶栏下方的白线按反馈移除 [用户选中的部件](../references/still-components.jpg)
- **字能读清, 还要能认出按钮**, 历史换色稿保留原按钮尺寸, 文字对按钮底色的对比度从 4.70:1 升至 7.08:1, 按钮底色对周围面板却从 3.78:1 降至 1.48:1, 可以在同一个按钮样件里单独试边线或底色 [换色实测](../evidence/still-history.md)
- **效果涉及背景, 就把背景一起带进样件**, 看全窗玻璃时要同时看亮处、暗处和文字覆盖处, 发现读不清时, 分别试底色、局部控件表面或文字颜色, 记录是哪项改动起了作用 [Apple 材质对照](../cases/apple-glass.md)
- **想比较版式, 就给各稿同一道题**, 旧五稿同时换了题材、数据和工作流, 改色后仍被撤下, 后来的五稿使用同一订单与审批状态, 可以直接比较哪张便于看时间、哪张便于核对字段, 新任务若已改变用户的主要动作, 重新选择适合该任务的布局 [同题设计与记录](../cases/index.md) · [Linear 影响分析](linear-influence.md)

仓库里的旧稿可以离线复核, 在仓库根目录运行 `python3 tools/verify.py`, 它会核对归档图片、图层读数和案例记录, 新稿的阅读顺序、按钮辨识度和实际点击状态仍需打开成稿检查
