# 给人或 Agent 的设计简报

填好方括号, 把下框交给设计者, 例如「用户要在 Mac 上审阅 Agent 提出的补丁, 看出两次发送属于同一订单, 最后决定是否打开补丁」

```text
方法仓库 https://github.com/wr-fenglei/agent-ui-design-method
打开 README.md 选底稿, 查布局看 foundations/linear.md, 查控件看 references/component-studies.md, 查玻璃看 cases/apple-glass.md

画什么
用户要做的事 = [谁, 在什么设备上, 看完什么证据, 做什么决定]
真实内容或明确标注的样例 = [当前对象, 用户请求, 原始数据, Agent 的发现, 验证结果, 还要人做的事]
底稿 = [可编辑原稿或链接, 打算保留的阅读顺序]
这张稿要解决的设计问题 = [要比较哪些信息, 或想在哪个地方采用什么效果]
指定的参考和反馈 = [原图及状态, 喜欢的地方, 需要避免的地方]

先研究再出稿
请打开原图, 从整屏找到相应控件和基础样式, 用能回答上述问题的官方示例或第三方产品实图对照
在 Figma 成稿旁做一块研究板, 将原件及状态、观察或实测、本稿决定、对应组件和检查结果放在一起
用自己的长文字、正常和选中等实际状态画原尺寸组件, 需要复用的做成主组件和实例
若涉及透明、阴影或折射, 另画一块真实背景上的样件, 写出图层顺序, 分别验证难以确定的效果
若参考与任务冲突, 记录直接采用、缩小范围或换回底稿部件的依据, 再决定整页怎么画

交付
研究与规范板 = [参考实物, 本稿层级, 原尺寸组件, 来源依据, 本稿定义]
可编辑整屏 = [节点或文件, 能定位到这次任务和关键操作]
原尺寸导出与检查 = [打开终稿可复查的部位, 发现的问题, 改动和复查结果]
还需人选的地方 = [有疑问时列两种具体处理及其差异]
```

例如「把导航行做得像 shadcn/ui」可以写成「看官网普通和选中行, 用本稿的长任务名复现 32 px 行高、16 px 图标和 8 px 图文间距, 再把组件放回真实侧栏看是否对齐」, 原件测量条件和本稿选择都可以留下 [组件库研究](../references/component-studies.md)
