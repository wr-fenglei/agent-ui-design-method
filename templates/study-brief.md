# 可复制的单来源制作简报

复制代码块, 将方括号替换为当前产品, 状态和验收任务, 制作多个候选时, 将整段共同任务原样传给每个来源

```text
产品与设备 = [设备, 视口, 工作区]
用户正在做的决定 = [本屏要回答的问题和要执行的动作]
事实与状态 = [用户请求, 真实或测试数据, 发生顺序, 产物, 成功或失败条件]
固定条件 = [文案事实, 数据, 设备, 可用动作]
本稿的来源 = [一个技能, 组件库, 产品或图库]
允许改变 = [内容组织, 布局, 材料, 排版, 控件]
其他视觉参考的曝光 = [是否提供, 哪张图, 版本, 或记录未知]

先交素材和规范
1. 找到官方示例和独立材料, 标出作者, 具体屏幕, 可见状态和链接
2. 本轮每个来源至少选 5 张用途不同的图, 对每张写清采用和舍弃的局部
3. 每条规则写: 控件/状态 | 一个变量 | 原图观察 | 本稿取值 | 出处 | 验收动作
4. 对每条负面提示写出会造成的具体问题和应如何检查
5. 记录哪些参数来自实测, 哪些由本稿决定, 哪些尚未验证

再交原生 Figma 稿与同尺寸导出图
1. 使用本来源规则安排用户请求, 证据, Agent 回复, 验证结果, 人工操作和追问
2. 在真实画面中检查默认, 选中和禁用等本次涉及的状态, 长文字按实际长度放入
3. 读回 Figma 图层, 复核必需字段, 关键控件, 图标与标签成组居中, 字色与实际背景对比
4. 导出 1× PNG, 走查整屏与局部, 将修正写回源文件, 重发原节点和重导
5. 交付来源, 规范与设计的对应链接, 写明已验证范围和需要用户选稿的问题
```

实际示例: Sentry 展开日志时字段紧接所选行, 本项目采用 0 px 展开间距, 若两个候选同时变化了行底色和间距, 后续测试可先固定底色, 只比较 0 px 与另一个预登记间距 [查看实作](../cases/mobbin/case.json)
