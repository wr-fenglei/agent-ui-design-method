# 给人或 Agent 的设计简报

复制下面这段, 填入本次任务即可

```text
方法仓库 https://github.com/wr-fenglei/agent-ui-design-method
产品、设备、尺寸和交付格式 = [...]
用户打开这屏要做的决定 = [...]
真实内容或标明的样例 = [当前对象, 必须同屏的证据, Agent 的结果, 下一步操作]
底稿和用户指定的参考 = [链接, 借哪部分, 哪些处理已被否决]

先打开一种同类产品的完整画面, 或一组来自同一设计系统的真实控件, 将原件里有关联的区域、字级和密度一并带入首稿, 其他来源只补欠缺的部件
下笔前写一行具体映射, 例如官网表格里的两行示例换成本题哪两条记录, 哪一栏随选中项变化, 官网原有的哪个模块可以删掉
写清哪些内容要放在一起, 哪些可以展开再看, 哪些可以删掉
如果这次要探索新整屏, 用相同内容比较至少两种不同构图, 改变阅读顺序、区域位置或证据呈现方式, 缩小并排看焦点, 记录选用和淘汰理由
用原尺寸组件完成入选稿, 导出后以 1× 对照参考, 核对标题和字段的起点、字级、字色、组内与组间留白、分割线以及图标和文字的居中
把目测导致的一次改动留成同位置的前后图, 说明为什么改和改后的结果, 若未发现问题就记录实际检查结果
只让不知道题目的人看成稿, 核对能否指出对象、证据和下一步, 另将成稿与参考并排做视觉评审, 审美偏好留给用户选

交付可编辑成稿与原尺寸预览, 将研究板放在成稿旁
板上留下原件与状态、信息取舍、尝试过的构图及淘汰理由、可定位的原尺寸部件、本稿取值、目测改稿和复核结果
如涉及材质再补图层、背景和对照实验, 标明来自原件的观察、测量和本稿自定的处理
```
